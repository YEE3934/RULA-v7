# RULA v9.2｜圖片完整顯示、分析區間裁切、Pose 手腕品質診斷

版本標記：`RULA_V9_2_IMAGE_SYNC_WRIST_QC_2026-10-28`

這一版直接從正常運作的 v9.1 版本修改，保留六個設定步驟、七個結果分頁、三鏡頭同步、MediaPipe Pose + Hand、RULA 評分、被剔除樣本複核、人工重新計分、時間軸及 ZIP 匯出。**沒有更換 RULA 查表或新增套件。**

## 修正項目

1. **時間同步預覽破圖**：從 `st.image(bytes)` 改用 JPEG 的 `data:image/jpeg;base64,...`，透過 `st.markdown(..., unsafe_allow_html=True)` 直接顯示，不經由 Streamlit 的 `/media` URL。
2. **照片縮圖只顯示上半部**：移除原本 `components.html(..., height=240)` 的固定高度 iframe，改用圖片自然比例 `height:auto`；在需要展開所有縮圖時先縮小圖片寬度節省記憶體。單張原圖仍保留在 ZIP。
3. **剔除影格、異常審核及 Pose/Hand 比較照片**：同樣採用不裁切的內嵌圖片版面。
4. **同步共同時間太早、前面全是空畫面**：在第 2 步的「三畫面同步預覽與微調」下方新增可選「實際分析起訖區間」滑桿。縮短到真正的動作期間，不需要重錄影片；也能打勾直接預覽所選分析起點的三鏡頭畫面。
5. **負秒數較難理解**：同步事件仍定義為共同時間 0 秒，事件之前仍是負的；但結果展示用的 `時間(秒)` 改成**本次裁切區間從 0 秒開始的分析經過時間**。詳細 `Synchronization/Frame_Time_Map.csv` 同時保留事件相對時間、每支影片原始時間和影格索引，沒有抹除同步資訊。
6. **Pose 偶發手腕怪值**：維持 Pose 作為預設正式計分、Hand 保留實驗比較。新增 `Pose手腕品質警示` 與 `Pose手腕需複核（保守）`：只有 >=65 度的極端角度或前後相近但中間突然偏離的孤立尖峰才標示。**不刪除影格、不擅自改角度、不修改 RULA 分數。**

## 這次兩張截圖的重點

- 第一張同步預覽圖片小圖示破圖：是網頁顯示路由問題；更換嵌入方式。
- 第二張多張縮圖都是天花板：一部分是舊版固定高度的圖片容器只顯示圖片上半部；此外，三支影片同步錨點在約 19.5～19.75 秒（靠近影片末端），舊版仍從共同時間 -19.5 秒開始取樣，可能包含動作開始前的空畫面。v9.2 顯示完整照片並允許裁切動作區間，這兩件事分開處理。

## 部署到 Streamlit Community Cloud

1. ZIP 解壓縮後，把 `RULA_v9_2_Deploy` **裡面的檔案**上傳到現有 GitHub 儲存庫根目錄，覆蓋 `222.py`。不要只上傳 ZIP 本身或把檔案留在子資料夾內。
2. Python 仍使用 **3.11**；Main file path：`222.py`。
3. 保留目前已成功運作的 `requirements.txt` / `packages.txt`。本部署包內同時附上相同設定。
4. `models/hand_landmarker.task` 模型檔若之前已上傳請保留。部署包不包含模型二進位檔。缺少時程式會嘗試從官方模型來源下載到可寫入的暫存目錄。
5. 網站最上方要看到 `RULA_V9_2_IMAGE_SYNC_WRIST_QC_2026-10-28`。如果還是 v9.1，代表尚未部署新檔。

## 建議的最短測試操作

1. 上傳三支同一次動作的影片，在第 2 步選取共同事件秒數。
2. **確認預覽圖全部能顯示，且畫面中的動作相同。**
3. 在第 2 步裁切到受測者確實進行搬運的時間，勾選「查看分析起點」確認不是空畫面，然後「確認同步」。
4. 到第 6 步啟動分析。
5. 結果分頁檢查「影格照片」的大圖、所有縮圖、剔除影格和手腕比較；應不再裁掉照片下半部。
6. 下載 ZIP，檢查 `Synchronization/Frame_Time_Map.csv`：`時間(秒)` 從 0 起算，而 `共同時間(秒)` 和 `Front/Right/Left影片時間(秒)` 保留原始同步資訊。

## 尚待科學驗證

- **Pose 跟 Hand 哪個更準**：你主觀量測覺得 Pose 較接近，這是有價值的初步觀察，仍不能代替使用相同標準角度進行定量誤差比較。保守警示僅標記少數候選值。
- **RULA 表格**：程式目前沿用原有 Table A / B / C；尚未對官方標準表格完成逐格獨立比對。
- **攝影機時戳**：目前仍以 FPS 與影格索引對應，對變動 FPS 的影片不等同逐影格 PTS 校準，若影片有 VFR、丟格或錄影時間漂移，需另外處理。
