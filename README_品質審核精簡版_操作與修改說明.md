# RULA 原穩定版｜品質審核流程精簡版（Q14）

**基礎檔案：** V12／V13 之前 `RULA_最終結案候選_完整版_20261030.zip` 的 `222.py`。本次沒有使用 V12 或 V13 的跨視角研究、離平面推論或角度替換機制。

## 修改原則

- **保留**原本完整功能：原始 RULA 角度與 Table A／B／C、三視角同步、左右側評分、手腕 Pose/Hand、人工補正、頸部共用、CSV/ZIP 輸出。
- **不修改**姿勢估測的計分公式與 RULA 總分。
- 只修改「骨架品質提醒／剔除樣本」的顯示與失敗診斷。

## 改了哪些部分

1. **不能計分：自動排除、免人工點選。** 程式本來就會排除無效側別；新版把這些紀錄獨立放在「自動排除（只查看原因）」，不再混進需要使用者處理的清單。若雙側同步其中一側失敗，另一側有效資料仍保留，但不生成缺側的雙側最高分。
2. **失敗原因具體化。** 在指定側已經計分失敗之後，針對該側面影格重新提取 Pose 關鍵點（不是原始那次的骨架快照），檢查肩、肘、腕、髖是否達到程式原有的 0.25 可見度門檻，也檢查耳／眼參考點。輸出「右手腕可見度不足」等可追查提示。若重新辨識正常但原本仍失敗，會如實標示「原因未能定位」，不會硬猜是哪一點。
3. **有分數但嚴重可疑：人工覆核。** 仍保留原品質演算法的審核要求，不會只為了減少提醒而強制放行。這類影格可查看原圖／骨架，決定維持、人工重評或剔除。
4. **一般品質留意：免操作。** 仍有資料記錄，但不要求逐張核對。品質提醒不等於角度精確，也不等於失敗。
5. **分頁分類及統計。** 介面分成「需要人工覆核／自動排除（只查看原因）／一般品質提醒／全部」，顯示各類數量。

## 你提供的品檢作業原始 ZIP（不是此版重新執行的結果）

- 30 張右手側抽樣；16 張原版已無有效分數；11 張有分數但嚴重品質疑慮；1 張一般留意；2 張品質通過。
- 新版應把 16 張顯示在「自動排除（只查看原因）」，11 張顯示「需要人工覆核」。需以實際重新跑同一部影片驗證，不保證 MediaPipe 逐次輸出永遠一致。
- 重要：16/30 不可用，是實際評估可用率問題；把它們移到免操作分頁只改善操作體驗，不會增加評分準確率。

## 如何更新測試網站

1. 在 GitHub 建立新的測試 repository，或備份原正式專案後使用此完整資料夾上傳；不建議直接覆蓋穩定正式版。
2. Python 3.11；主程式 `222.py`；依 `requirements.txt` 安裝，必要的模型下載腳本在 `scripts/`。
3. 用原本「品檢」的 Front＋Right 影片和相同抽樣設定執行30張。
4. 進入「剔除樣本」或「骨架品質審核」頁，查看4類計數、排除原因、原圖與骨架。
5. 下載分析 ZIP，檢查 `技術診斷/辨識失敗.csv` 的「可能原因／關鍵點檢查結果／不符合門檻關鍵點／診斷方式」欄。`技術診斷/待處理影格.csv` 記錄原因與圖片路徑。注意：ZIP 中歷史名稱「待處理影格」仍可能包含自動排除紀錄，網頁會將它們分開顯示。
6. 對照原版 RULA Table A/B/C 和同一批有效分數應沒有因本次修改而改變；若有差異先檢查影片同步、模型與作業設定。

## 限制

- **不具備**自動離平面辨識、多相機3D重建、跨視角量角替換，也不聲稱解決遮擋或增加量角準確率。
- 「失敗後重新擷取」只作故障診斷，可能與正式分析的關鍵點估測不同。若無法確定，會明確標示。
- 仍保留嚴重疑慮樣本的人工覆核；不是全部警示都剔除。
- 由於目前執行環境沒有 Streamlit 與 MediaPipe，完成靜態語法和63項獨立測試，但尚未在你的實際影片上進行完整網頁端到端重跑。
